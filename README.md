# Сейф - исходный код

«Сейф» - менеджер паролей и важных данных для Android: пароли, банковские карты, документы, коды 2FA, seed-фразы, реквизиты, заметки. Приложение в RuStore: https://www.rustore.ru/catalog/app/ru.dorokhin.seyf

Здесь лежит исходный код версии 1.3.3 (versionCode 20607) - той, что опубликована в RuStore.

## Зачем код открыт

Менеджеру паролей нельзя верить на слово. Код открыт, чтобы любой мог сам проверить две вещи: что данные не уходят в сеть и как устроено шифрование. Все утверждения ниже можно сверить с файлами, на которые они ссылаются.

## Как устроено приложение

Это Capacitor-приложение: интерфейс и вся логика написаны на JavaScript (папка `www/`) и работают внутри WebView, нативная часть на Java (папка `android/`) - это оболочка, окно сохранения файла, печать листа «Архива для близких», системный размер шрифта и мосты к трём SDK RuStore: оплата, обновление приложения и окно оценки.

## Как хранятся данные

- Все записи сейфа хранятся в одном зашифрованном файле `vault.dat` в приватной папке приложения (`Directory.Data` плагина Filesystem). См. `www/js/storage.js`, строки 1-7.
- Шифрование данных: AES-256-GCM, для каждой записи файла новый случайный вектор инициализации 12 байт. Работает на стандартном WebCrypto (`crypto.subtle`), своей криптографии нет. См. `www/js/crypto.js`, строки 37-44.
- Ключ шифрования данных (DEK) - 32 случайных байта. В файле он не лежит в открытом виде, только в зашифрованном («обёрнутом») виде. См. `www/js/crypto.js`, строки 58-73.
- Ключ из мастер-пароля: PBKDF2-SHA-256, 600 000 итераций, случайная соль 16 байт. Этим ключом обёрнут DEK. Неверный пароль просто не расшифрует DEK. См. `www/js/crypto.js`, строки 24-33 и 58-84.
- Смена мастер-пароля заново оборачивает тот же DEK новым паролем с новой солью. См. `www/js/crypto.js`, строки 91-98.
- Мастер-пароль нигде не сохраняется. Если его забыть и биометрия не включена, данные не восстановить.
- Вне зашифрованного файла, в хранилище WebView (`localStorage`), лежат только настройки: тема, скрытые разделы, включён ли вход по биометрии, отметка «буфер обмена надо очистить» (без самого секрета) и подсказка к мастер-паролю, если пользователь её задал. Подсказка хранится открыто, иначе её нельзя показать до разблокировки. См. `www/js/biopref.js`, строки 41-54, и `www/js/app.js`, строки 56-62. С версии 1.3.2 там же служебные отметки без содержимого записей: показано ли знакомство (`www/js/onboard.js`, строка 9), скрыто ли предупреждение в разделе seed-фраз и было ли напоминание после первой фразы (`www/js/seed.js`, строки 66 и 82), когда и сколько раз показывалось окно оценки (`www/js/review.js`, строки 20-21 и 27), когда приложение последний раз спрашивало RuStore об обновлении и нашлась ли новая версия (`www/storeupdate.js`, строки 25-26). С версии 1.3.3 - отметки двух напоминаний, только даты и выключатель: о резервной копии раз в месяц (`www/js/backupnudge.js`, строки 8-17) и об «Архиве для близких» раз в полгода (`www/js/archive.js`, строки 676-685).
- Файл сейфа не попадает в облачную резервную копию Android и не переносится при смене телефона: `allowBackup="false"` и правила `data_extraction_rules.xml`. См. `android/app/src/main/AndroidManifest.xml`, строки 4-8, и `android/app/src/main/res/xml/data_extraction_rules.xml`.
- Резервная копия, которую делает сам пользователь (`vault-backup-ДАТА.dat`), - это тот же зашифрованный файл. Он сохраняется только туда, куда пользователь сам укажет в системном окне сохранения. См. `www/js/app.js`, строки 1968-1985, и `android/app/src/main/java/ru/dorokhin/seyf/SaveFilePlugin.java`.

## Архив для близких (новое в 1.3.3)

- Записи архива хранятся внутри того же зашифрованного файла сейфа (`vault.archive`) и попадают в резервную копию `.dat`. См. `www/js/archive.js`, строки 9-11.
- «Только основная информация» - лист без логинов, паролей, ПИН-кодов и номеров карт. Это статичный HTML без скриптов, сеть в нём запрещена правилом `default-src 'none'`. См. `www/js/archive.js`, строки 493-496. Печать идёт через системное окно печати Android (там же «Сохранить как PDF»): лист открывается в отдельном WebView с выключенным JavaScript и запретом сетевых загрузок. См. `android/app/src/main/java/ru/dorokhin/seyf/PrintPlugin.java`, строки 84-89, и `www/js/archive-ui.js`, строки 375-379.
- «Основная информация + логины и пароли» - файл под отдельным паролем: PBKDF2-SHA-256, 600 000 итераций, AES-GCM, тот же WebCrypto. См. `www/js/archive.js`, строки 571-593. Пароль файла не может совпадать с мастер-паролем: приложение проверяет это снятием обёртки ключа, ничего не сохраняя (`www/js/archive.js`, строки 559-567, `www/js/archive-ui.js`, строка 306).
- Этот файл - самодостаточная HTML-страница: внутри только шифртекст и код расшифровки, правило `default-src 'none'` не даёт ей обращаться к сети. Открывается паролем в любом браузере. См. `www/js/archive.js`, строки 628-643.
- Лист и файл сохраняются только туда, куда пользователь сам укажет в системном окне сохранения, как и резервная копия. См. `www/js/archive-ui.js`, строки 346-357.

## Что делает биометрия

- При включении входа по биометрии приложение создаёт случайный ключ 32 байта и оборачивает им тот же DEK (поле `helloWrap` в файле сейфа). См. `www/js/app.js`, строки 1585-1588, и `www/js/crypto.js`, строки 100-105.
- Этот ключ сохраняется через плагин `capacitor-native-biometric` 4.2.2: плагин шифрует его ключом из Android Keystore и кладёт в приватные настройки приложения. См. `www/js/auth.js`.
- Перед тем как достать ключ, приложение показывает системное окно биометрии. См. `www/js/app.js`, строки 1430-1432.
- Честное уточнение: в этой версии ключ Keystore, которым плагин шифрует сохранённый ключ, не привязан к биометрии на уровне самого Keystore. Биометрия здесь - проверка перед доступом, а не криптографическое условие расшифровки. Мастер-пароль остаётся основным входом, биометрия - дополнительным удобством.

## Сетевые обращения

Ниже все места в коде, где приложение может обратиться к сети.

1. **RuStore Pay** (покупка полной версии). Нативный SDK RuStore (`ru.rustore.sdk:pay`) используется для оплаты и для проверки, куплена ли полная версия. Проверка покупки выполняется при нажатии «Купить» или «Восстановить покупку» и тихо после разблокировки сейфа, если полная версия ещё не отмечена. Данные сейфа в эти вызовы не передаются, только идентификатор товара `seyf-pro`. Что SDK передаёт серверам RuStore, определяет RuStore. См. `android/app/src/main/java/ru/dorokhin/seyf/RuStorePayPlugin.java`, `www/js/payment.js`, `www/js/pay.js`, `www/js/purchase.js`, `www/js/app.js`, строки 1666-1671, `android/app/build.gradle`, строки 75-76.
2. **Проверка обновлений через RuStore** (новое в 1.3.2). В сборке для RuStore свой канал обновлений выключен целиком: функции проверки и загрузки в `www/update.js` отказываются до любого сетевого запроса. См. `www/update.js`, строки 1-15, 429, 471, 866, 882. Вместо него строка версии с кнопкой «Проверить» в окне «О приложении» (до 1.3.3 - пункт меню «Обновление») спрашивает установленное на телефоне приложение RuStore через нативный RuStore App Update SDK (`ru.rustore.sdk:appupdate`): по кнопке «Проверить» и тихо не чаще раза в неделю при запуске. Кнопка «Обновить» запускает обновление в RuStore или открывает страницу приложения в RuStore. Веб-часть при этом сама в сеть не ходит, она только вызывает нативный плагин. См. `www/storeupdate.js` (логика и строки окна), `www/update.js`, строки 832-837 и 1341, `android/app/src/main/java/ru/dorokhin/seyf/RuStoreUpdatePlugin.java`, `android/app/build.gradle`, строки 77-79. В тестовых сборках вне RuStore `www/update.js` вместо этого запрашивает файл с номером версии с `https://dorokhin-finance.ru/seyf-store/update.json`; сведения о пользователе при этом не отправляются.
3. **Окно оценки RuStore** (новое в 1.3.2). Только в сборке для RuStore, сразу после сохранения новой записи, если приложением пользуются 7-й день и в сейфе 10 записей; не больше двух раз за всё время. Показывает системное окно RuStore Review SDK (`ru.rustore.sdk:review`), своей кнопки «Оценить» нет. В вызов не передаётся ничего из сейфа: плагин вызывается без параметров, приложение считает только число записей у себя. См. `www/js/review.js`, строки 1-21, `www/js/app.js`, строки 1115-1137 и 3610, `android/app/src/main/java/ru/dorokhin/seyf/RuStoreReviewPlugin.java`, строки 52-87, `android/app/build.gradle`, строки 80-82.
4. **Запрет сети для веб-части в сборке для RuStore.** Сборка заменяет в `index.html` правило Content-Security-Policy на `connect-src 'none'`: даже случайный запрос из JavaScript наружу WebView не выпустит. Нативные SDK RuStore (пункты 1-3) этим правилом не ограничены. См. `build-lib.js`, строки 226-229, и `build-apk.js`, строка 137.
5. **Ссылки, которые открывает сам пользователь.** Нажатие на ссылку в карточке контакта или в окне «О приложении» (политика конфиденциальности, соглашение, сайт автора) открывает её в системном браузере или другом приложении. Само приложение при этом ничего не загружает. С версии 1.3.3 в «О приложении» есть «Частые вопросы», в одном из них ссылка на этот репозиторий (`www/js/faq.js`, строки 35-36), а кнопка «Открыть RuStore» в окне покупки открывает страницу приложения в RuStore (`www/js/app.js`, строки 224-230). См. `www/js/app.js`, строки 2453-2479 и 3665-3671.

Других `fetch`, `XMLHttpRequest`, `WebSocket` в коде приложения (без сторонних библиотек из `www/vendor/` и `www/capacitor.js`) нет: единственные вызовы `fetch` находятся в `www/update.js` (строки 1136 и 1153), один из них читает локальный `files.json`. Новые модули 1.3.2 (`www/storeupdate.js`, `www/js/review.js`, `www/js/onboard.js`) и 1.3.3 (`www/js/archive.js`, `www/js/archive-ui.js`, `www/js/backupnudge.js`, `www/js/faq.js`, `www/js/fontzoom.js`, `www/js/purchase.js`, `www/js/syswindow.js`) сетевых вызовов не содержат. Проверить: `grep -rn "fetch(\|XMLHttpRequest\|WebSocket" www --include=*.js`.

## Разрешения Android

Из `android/app/src/main/AndroidManifest.xml` (строки 76-85):

- `INTERNET` - нужен SDK RuStore (покупка и проверка покупки, с 1.3.2 ещё проверка обновления и окно оценки), а также WebView для работы с локальными файлами приложения по адресу `https://localhost`.
- `USE_BIOMETRIC` - вход по отпечатку или лицу (см. раздел про биометрию).
- `CAMERA` - сканирование QR-кода при добавлении кода 2FA (`www/js/qr-scan.js`, строки 59-98) и фото документов через штатное приложение камеры (`www/js/doc-viewer.js`, строки 443-463). Камера не обязательна: `android.hardware.camera` с `required="false"`, секрет 2FA можно ввести вручную. Временные JPEG, которые камера оставляет в папке приложения, удаляются после съёмки и при запуске (`www/js/camtemp.js`); в сейф попадает только зашифрованная копия.

Блок `<queries>` (строки 66-74 того же файла, новое в 1.3.2) - не разрешение: он только позволяет приложению на Android 11 и новее увидеть установленный RuStore, чтобы проверить обновление и показать окно оценки.

Новые в 1.3.3 нативные плагины печати и размера шрифта (`PrintPlugin.java`, `FontScalePlugin.java`) разрешений не требуют.

Подключённые библиотеки добавляют свои разрешения при сборке APK. Итоговый список в APK 1.3.3 из RuStore (`aapt2 dump permissions`): `INTERNET`, `USE_BIOMETRIC`, `CAMERA`, `VIBRATE`, `USE_FINGERPRINT`, `ACCESS_NETWORK_STATE`, `RECEIVE_BOOT_COMPLETED` и служебное `ru.dorokhin.seyf.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`; он совпадает со списком версии 1.3.2. `VIBRATE` добавляет плагин `@capacitor/haptics` (вибро-отклик на ключевых действиях, `www/js/app.js`, строки 3720-3723).

## Другие меры защиты

- Запрет скриншотов и записи экрана (`FLAG_SECURE`) и выключенная отладка WebView в релизной сборке. См. `android/app/src/main/java/ru/dorokhin/seyf/MainActivity.java`, строки 36-47.
- Поля сейфа исключены из системного автозаполнения Android. См. там же, строки 54-58.
- Лицензионный ключ полной версии проверяется офлайн по подписи ECDSA P-256; в приложение вшит только публичный ключ. См. `www/js/license.js`, строки 1-14.

## Чем исходник отличается от сборки в RuStore

Скрипт `build-apk.js --store` берёт папку `www/` и меняет в копии три вещи: в `buildflags.js` ставит `SEYF_STORE = true` и `SEYF_DEMO = false`, в `js/demo.js` выключает демо-режим, в `index.html` ставит `connect-src 'none'`. Ещё при сборке создаются служебные файлы: опись файлов `files.json` (`build-lib.js`, строки 243-262) и заглушки `cordova.js` и `cordova_plugins.js`, которые добавляет `npx cap sync` (`build-apk.js`, строка 154). Остальные файлы попадают в APK без изменений. См. `build-lib.js`, строки 181-233.

## Как проверить самому

1. **Режим полёта.** Включите режим полёта и пользуйтесь сейфом: создание, разблокировка, запись, резервная копия работают без сети. Без сети не сработают только покупка, восстановление покупки и проверка обновления через RuStore. «Архив для близких» тоже работает без сети.
2. **Прочитать шифрование.** Весь криптографический код сейфа - 115 строк в `www/js/crypto.js`. Как он вызывается - `www/js/app.js` и `www/js/storage.js`. Шифрование файла «Архива для близких» - `www/js/archive.js`, строки 571-643.
3. **Найти сетевые вызовы.** Команда из раздела «Сетевые обращения» выше.
4. **Запустить тесты.** Нужен Node.js 20 или новее:

   ```
   npm install
   npm test
   ```

   На момент публикации: 1124 проверки, 1102 проходят, 0 падают, 22 пропускаются: им нужны приватные ключи подписи, внутренние скрипты публикации обновлений и проверки экранов или файлы карточки и скриншотов RuStore, которые в этот репозиторий не входят (причина пропуска печатается рядом с каждой такой проверкой). Тесты шифрования - `tests/crypto.test.mjs` и `tests/auth-crypto.test.mjs`.

## Сборка APK

`node build-apk.js` собирает тестовый APK (нужны JDK и Android SDK). Релизная сборка подписывается ключом автора, которого здесь нет, поэтому подпись вашего APK не совпадёт с приложением из RuStore.

## Лицензия

Код открыт только для просмотра и проверки. Распространять копии, собирать и публиковать свои версии, использовать код в других продуктах нельзя. Подробно - в файле `LICENSE`.

Сторонние библиотеки в `www/vendor/` (jsQR, pdf.js, fflate, шрифты) распространяются по своим лицензиям.
