# Сейф - исходный код

«Сейф» - менеджер паролей и важных данных для Android: пароли, банковские карты, документы, коды 2FA, seed-фразы, реквизиты, заметки. Приложение в RuStore: https://www.rustore.ru/catalog/app/ru.dorokhin.seyf

Здесь лежит исходный код версии 1.3.1 - той, что опубликована в RuStore.

## Зачем код открыт

Менеджеру паролей нельзя верить на слово. Код открыт, чтобы любой мог сам проверить две вещи: что данные не уходят в сеть и как устроено шифрование. Все утверждения ниже можно сверить с файлами, на которые они ссылаются.

## Как устроено приложение

Это Capacitor-приложение: интерфейс и вся логика написаны на JavaScript (папка `www/`) и работают внутри WebView, нативная часть на Java (папка `android/`) - это оболочка, окно сохранения файла и мост к оплате RuStore.

## Как хранятся данные

- Все записи сейфа хранятся в одном зашифрованном файле `vault.dat` в приватной папке приложения (`Directory.Data` плагина Filesystem). См. `www/js/storage.js`, строки 1-7.
- Шифрование данных: AES-256-GCM, для каждой записи файла новый случайный вектор инициализации 12 байт. Работает на стандартном WebCrypto (`crypto.subtle`), своей криптографии нет. См. `www/js/crypto.js`, строки 37-44.
- Ключ шифрования данных (DEK) - 32 случайных байта. В файле он не лежит в открытом виде, только в зашифрованном («обёрнутом») виде. См. `www/js/crypto.js`, строки 58-73.
- Ключ из мастер-пароля: PBKDF2-SHA-256, 600 000 итераций, случайная соль 16 байт. Этим ключом обёрнут DEK. Неверный пароль просто не расшифрует DEK. См. `www/js/crypto.js`, строки 24-33 и 58-84.
- Смена мастер-пароля заново оборачивает тот же DEK новым паролем с новой солью. См. `www/js/crypto.js`, строки 91-98.
- Мастер-пароль нигде не сохраняется. Если его забыть и биометрия не включена, данные не восстановить.
- Вне зашифрованного файла, в хранилище WebView (`localStorage`), лежат только настройки: тема, скрытые разделы, включён ли вход по биометрии, отметка «буфер обмена надо очистить» (без самого секрета) и подсказка к мастер-паролю, если пользователь её задал. Подсказка хранится открыто, иначе её нельзя показать до разблокировки. См. `www/js/biopref.js`, строки 41-54, и `www/js/app.js`, строки 44-52.
- Файл сейфа не попадает в облачную резервную копию Android и не переносится при смене телефона: `allowBackup="false"` и правила `data_extraction_rules.xml`. См. `android/app/src/main/AndroidManifest.xml`, строки 4-8, и `android/app/src/main/res/xml/data_extraction_rules.xml`.
- Резервная копия, которую делает сам пользователь (`vault-backup-ДАТА.dat`), - это тот же зашифрованный файл. Он сохраняется только туда, куда пользователь сам укажет в системном окне сохранения. См. `www/js/app.js`, строки 1685-1702, и `android/app/src/main/java/ru/dorokhin/seyf/SaveFilePlugin.java`.

## Что делает биометрия

- При включении входа по биометрии приложение создаёт случайный ключ 32 байта и оборачивает им тот же DEK (поле `helloWrap` в файле сейфа). См. `www/js/app.js`, строки 1375-1378, и `www/js/crypto.js`, строки 100-105.
- Этот ключ сохраняется через плагин `capacitor-native-biometric` 4.2.2: плагин шифрует его ключом из Android Keystore и кладёт в приватные настройки приложения. См. `www/js/auth.js`.
- Перед тем как достать ключ, приложение показывает системное окно биометрии. См. `www/js/app.js`, строки 1263-1265.
- Честное уточнение: в этой версии ключ Keystore, которым плагин шифрует сохранённый ключ, не привязан к биометрии на уровне самого Keystore. Биометрия здесь - проверка перед доступом, а не криптографическое условие расшифровки. Мастер-пароль остаётся основным входом, биометрия - дополнительным удобством.

## Сетевые обращения

Ниже все места в коде, где приложение может обратиться к сети.

1. **RuStore Pay** (покупка полной версии). Нативный SDK RuStore (`ru.rustore.sdk:pay`) используется для оплаты и для проверки, куплена ли полная версия. Проверка покупки выполняется при нажатии «Купить» или «Восстановить покупку» и тихо после разблокировки сейфа, если полная версия ещё не отмечена. Данные сейфа в эти вызовы не передаются, только идентификатор товара `seyf-pro`. Что SDK передаёт серверам RuStore, определяет RuStore. См. `android/app/src/main/java/ru/dorokhin/seyf/RuStorePayPlugin.java`, `www/js/payment.js`, `www/js/pay.js`, `www/js/app.js`, строки 1394-1398, `android/app/build.gradle`, строки 75-76.
2. **Проверка обновлений** (`www/update.js`). В сборке для RuStore она выключена целиком: все функции проверки и загрузки обновлений отказываются до любого сетевого запроса, пункт «Обновление» только объясняет, что обновления приходят через RuStore. См. `www/update.js`, строки 1-13, 427, 469, 745, 774, 790. В тестовых сборках вне RuStore этот модуль запрашивает файл с номером версии с `https://dorokhin-finance.ru/seyf-store/update.json`; сведения о пользователе при этом не отправляются.
3. **Запрет сети для веб-части в сборке для RuStore.** Сборка заменяет в `index.html` правило Content-Security-Policy на `connect-src 'none'`: даже случайный запрос из JavaScript наружу WebView не выпустит. Нативный SDK RuStore (пункт 1) этим правилом не ограничен. См. `build-lib.js`, строки 226-229, и `build-apk.js`, строка 135.
4. **Ссылки, которые открывает сам пользователь.** Нажатие на ссылку в карточке контакта или в окне «О приложении» (политика конфиденциальности, соглашение, сайт автора) открывает её в системном браузере или другом приложении. Само приложение при этом ничего не загружает. См. `www/js/app.js`, строки 2145-2164 и 3264-3270.

Других `fetch`, `XMLHttpRequest`, `WebSocket` в коде приложения (без сторонних библиотек из `www/vendor/` и `www/capacitor.js`) нет: единственные вызовы `fetch` находятся в `www/update.js` (строки 1044 и 1061), один из них читает локальный `files.json`. Проверить: `grep -rn "fetch(\|XMLHttpRequest\|WebSocket" www --include=*.js`.

## Разрешения Android

Из `android/app/src/main/AndroidManifest.xml` (строки 66-75):

- `INTERNET` - нужен RuStore Pay SDK для покупки и проверки покупки, а также WebView для работы с локальными файлами приложения по адресу `https://localhost`.
- `USE_BIOMETRIC` - вход по отпечатку или лицу (см. раздел про биометрию).
- `CAMERA` - сканирование QR-кода при добавлении кода 2FA (`www/js/qr-scan.js`, строки 59-98) и фото документов через штатное приложение камеры (`www/js/doc-viewer.js`, строки 443-463). Камера не обязательна: `android.hardware.camera` с `required="false"`, секрет 2FA можно ввести вручную. Временные JPEG, которые камера оставляет в папке приложения, удаляются после съёмки и при запуске (`www/js/camtemp.js`); в сейф попадает только зашифрованная копия.

Подключённые библиотеки могут добавить свои разрешения при сборке APK. Итоговый список виден в карточке приложения в RuStore или командой `aapt dump permissions` по APK.

## Другие меры защиты

- Запрет скриншотов и записи экрана (`FLAG_SECURE`) и выключенная отладка WebView в релизной сборке. См. `android/app/src/main/java/ru/dorokhin/seyf/MainActivity.java`, строки 32-43.
- Поля сейфа исключены из системного автозаполнения Android. См. там же, строки 48-52.
- Лицензионный ключ полной версии проверяется офлайн по подписи ECDSA P-256; в приложение вшит только публичный ключ. См. `www/js/license.js`, строки 1-14.

## Чем исходник отличается от сборки в RuStore

Скрипт `build-apk.js --store` берёт папку `www/` и меняет в копии три вещи: в `buildflags.js` ставит `SEYF_STORE = true` и `SEYF_DEMO = false`, в `js/demo.js` выключает демо-режим, в `index.html` ставит `connect-src 'none'`. Ещё при сборке создаются служебные файлы: опись файлов `files.json` (`build-lib.js`, строки 243-262) и заглушки `cordova.js` и `cordova_plugins.js`, которые добавляет `npx cap sync` (`build-apk.js`, строка 152). Остальные файлы попадают в APK без изменений. См. `build-lib.js`, строки 181-233.

## Как проверить самому

1. **Режим полёта.** Включите режим полёта и пользуйтесь сейфом: создание, разблокировка, запись, резервная копия работают без сети. Без сети не сработают только покупка и восстановление покупки через RuStore.
2. **Прочитать шифрование.** Весь криптографический код - 115 строк в `www/js/crypto.js`. Как он вызывается - `www/js/app.js` и `www/js/storage.js`.
3. **Найти сетевые вызовы.** Команда из раздела «Сетевые обращения» выше.
4. **Запустить тесты.** Нужен Node.js 20 или новее:

   ```
   npm install
   npm test
   ```

   На момент публикации: 805 проверок, 790 проходят, 0 падают, 15 пропускаются: им нужны приватные ключи подписи или внутренние скрипты публикации обновлений, которые в этот репозиторий не входят (причина пропуска печатается рядом с каждой такой проверкой). Тесты шифрования - `tests/crypto.test.mjs` и `tests/auth-crypto.test.mjs`.

## Сборка APK

`node build-apk.js` собирает тестовый APK (нужны JDK и Android SDK). Релизная сборка подписывается ключом автора, которого здесь нет, поэтому подпись вашего APK не совпадёт с приложением из RuStore.

## Лицензия

Код открыт только для просмотра и проверки. Распространять копии, собирать и публиковать свои версии, использовать код в других продуктах нельзя. Подробно - в файле `LICENSE`.

Сторонние библиотеки в `www/vendor/` (jsQR, pdf.js, fflate, шрифты) распространяются по своим лицензиям.
