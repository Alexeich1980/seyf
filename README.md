# Сейф - исходный код

«Сейф» - менеджер паролей и важных данных для Android: пароли, банковские и дисконтные карты, документы, коды 2FA, seed-фразы, реквизиты, заметки. Приложение в RuStore: https://www.rustore.ru/catalog/app/ru.dorokhin.seyf

Исходный код «Сейфа» 1.3.4 для Android (versionCode 20609). Список изменений приведён в [CHANGELOG.md](CHANGELOG.md).

## Зачем код открыт

По исходному коду можно проверить, как работает шифрование, какие данные хранятся на устройстве и где приложение обращается к RuStore.

## Как устроено приложение

Это Capacitor-приложение: интерфейс и вся логика написаны на JavaScript (папка `www/`) и работают внутри WebView, нативная часть на Java (папка `android/`) - это оболочка, окно сохранения файла, печать листа «Архива для близких», системный размер шрифта, яркость экрана с дисконтной картой, уведомления о сроках документов и мосты к трём SDK RuStore: оплата, обновление приложения и окно оценки.

## Как хранятся данные

- Все записи сейфа хранятся в одном зашифрованном файле `vault.dat` в приватной папке приложения (`Directory.Data` плагина Filesystem). См. `www/js/storage.js`, строки 1-7.
- Шифрование данных: AES-256-GCM, для каждой записи файла новый случайный вектор инициализации 12 байт. Работает на стандартном WebCrypto (`crypto.subtle`), своей криптографии нет. См. `www/js/crypto.js`, строки 37-44.
- Ключ шифрования данных (DEK) - 32 случайных байта. В файле он не лежит в открытом виде, только в зашифрованном («обёрнутом») виде. См. `www/js/crypto.js`, строки 58-73.
- Ключ из мастер-пароля: PBKDF2-SHA-256, 600 000 итераций, случайная соль 16 байт. Этим ключом обёрнут DEK. Неверный пароль просто не расшифрует DEK. См. `www/js/crypto.js`, строки 24-33 и 58-84.
- Смена мастер-пароля заново оборачивает тот же DEK новым паролем с новой солью. См. `www/js/crypto.js`, строки 91-98.
- Мастер-пароль нигде не сохраняется. Если его забыть и биометрия не включена, данные не восстановить.
- Вне зашифрованного файла, в хранилище WebView (`localStorage`), лежат только настройки: тема, скрытые разделы, включён ли вход по биометрии, отметка «буфер обмена надо очистить» (без самого секрета) и подсказка к мастер-паролю, если пользователь её задал. Подсказка хранится открыто, иначе её нельзя показать до разблокировки. См. `www/js/biopref.js`, строки 41-54, и `www/js/app.js`. С версии 1.3.2 там же служебные отметки без содержимого записей: показано ли знакомство (`www/js/onboard.js`, строка 9), скрыто ли предупреждение в разделе seed-фраз и было ли напоминание после первой фразы (`www/js/seed.js`, строки 66 и 82), когда и сколько раз показывалось окно оценки (`www/js/review.js`, строки 20-21 и 27), когда приложение последний раз спрашивало RuStore об обновлении и нашлась ли новая версия (`www/storeupdate.js`, строки 25-26). С версии 1.3.3 - отметки двух напоминаний, только даты и выключатель: о резервной копии раз в месяц (`www/js/backupnudge.js`, строки 8-17) и об «Архиве для близких» раз в полгода (`www/js/archive.js`).
- Файл сейфа не попадает в облачную резервную копию Android и не переносится при смене телефона: `allowBackup="false"` и правила `data_extraction_rules.xml`. См. `android/app/src/main/AndroidManifest.xml`, строки 4-8, и `android/app/src/main/res/xml/data_extraction_rules.xml`.
- Резервная копия, которую делает сам пользователь (`vault-backup-ДАТА.dat`), - это тот же зашифрованный файл. Он сохраняется только туда, куда пользователь сам укажет в системном окне сохранения. См. `www/js/app.js` и `android/app/src/main/java/ru/dorokhin/seyf/SaveFilePlugin.java`.

## Архив для близких

- Записи архива хранятся внутри того же зашифрованного файла сейфа (`vault.archive`) и попадают в резервную копию `.dat`. См. `www/js/archive.js`.
- «Только основная информация» - лист без логинов, паролей, ПИН-кодов и номеров карт. Это статичный HTML без скриптов, сеть в нём запрещена правилом `default-src 'none'`. См. `www/js/archive.js`. Печать идёт через системное окно печати Android (там же «Сохранить как PDF»): лист открывается в отдельном WebView с выключенным JavaScript и запретом сетевых загрузок. См. `android/app/src/main/java/ru/dorokhin/seyf/PrintPlugin.java`, строки 84-89, и `www/js/archive-ui.js`.
- «Основная информация + логины и пароли» - файл под отдельным паролем: PBKDF2-SHA-256, 600 000 итераций, AES-GCM, тот же WebCrypto. См. `www/js/archive.js`. Пароль файла не может совпадать с мастер-паролем: приложение проверяет это снятием обёртки ключа, ничего не сохраняя (`www/js/archive.js`, `www/js/archive-ui.js`, строка 306).
- Для нового файла генератор предлагает пароль из шести случайных слов. Ранее созданные архивы открываются своими паролями. Этот файл - самодостаточная HTML-страница: внутри только шифртекст и код расшифровки, правило `default-src 'none'` не даёт ей обращаться к сети. Открывается паролем в любом браузере. См. `www/js/archive.js`.
- Лист и файл сохраняются только туда, куда пользователь сам укажет в системном окне сохранения, как и резервная копия. См. `www/js/archive-ui.js`.

## Что делает биометрия

- При включении входа по биометрии приложение создаёт случайный ключ 32 байта и оборачивает им тот же DEK (поле `helloWrap` в файле сейфа). См. `www/js/app.js` и `www/js/crypto.js`, строки 100-105.
- Этот ключ сохраняется через плагин `capacitor-native-biometric` 4.2.2: плагин шифрует его ключом из Android Keystore и кладёт в приватные настройки приложения. См. `www/js/auth.js`.
- Перед тем как достать ключ, приложение показывает системное окно биометрии. См. `www/js/app.js`.
- Честное уточнение: в этой версии ключ Keystore, которым плагин шифрует сохранённый ключ, не привязан к биометрии на уровне самого Keystore. Биометрия здесь - проверка перед доступом, а не криптографическое условие расшифровки. Мастер-пароль остаётся основным входом, биометрия - дополнительным удобством.

## Сетевые обращения

Сборка для RuStore обращается к магазину через его нативные SDK. Поведение SDK проверяется отдельно от кода WebView.

1. **RuStore Pay** (покупка полной версии). Нативный SDK RuStore (`ru.rustore.sdk:pay`) используется для оплаты и для проверки, куплена ли полная версия. Проверка покупки выполняется при нажатии «Купить» или «Восстановить покупку» и тихо после разблокировки сейфа, если полная версия ещё не отмечена. Данные сейфа в эти вызовы не передаются, только идентификатор товара `seyf-pro`. Что SDK передаёт серверам RuStore, определяет RuStore. См. `android/app/src/main/java/ru/dorokhin/seyf/RuStorePayPlugin.java`, `www/js/payment.js`, `www/js/pay.js`, `www/js/purchase.js`, `www/js/app.js`, `android/app/build.gradle`, строки 75-76.
2. **Проверка обновлений через RuStore** (новое в 1.3.2). В сборке для RuStore свой канал обновлений выключен целиком: функции проверки и загрузки в `www/update.js` отказываются до любого сетевого запроса. См. `www/update.js`, строки 1-15, 429, 471, 866, 882. Вместо него строка версии с кнопкой «Проверить» в окне «О приложении» (до 1.3.3 - пункт меню «Обновление») спрашивает установленное на телефоне приложение RuStore через нативный RuStore App Update SDK (`ru.rustore.sdk:appupdate`): по кнопке «Проверить» и тихо не чаще раза в неделю при запуске. Кнопка «Обновить» запускает обновление в RuStore или открывает страницу приложения в RuStore. Веб-часть при этом сама в сеть не ходит, она только вызывает нативный плагин. См. `www/storeupdate.js` (логика и строки окна), `www/update.js`, строки 832-837 и 1341, `android/app/src/main/java/ru/dorokhin/seyf/RuStoreUpdatePlugin.java`, `android/app/build.gradle`, строки 77-79. В тестовых сборках вне RuStore `www/update.js` вместо этого запрашивает файл с номером версии с `https://dorokhin-finance.ru/seyf-store/update.json`; сведения о пользователе при этом не отправляются.
3. **Окно оценки RuStore** (новое в 1.3.2). Только в сборке для RuStore, сразу после сохранения новой записи, если приложением пользуются 7-й день и в сейфе 10 записей; не больше двух раз за всё время. Показывает системное окно RuStore Review SDK (`ru.rustore.sdk:review`), своей кнопки «Оценить» нет. В вызов не передаётся ничего из сейфа: плагин вызывается без параметров, приложение считает только число записей у себя. См. `www/js/review.js`, строки 1-21, `www/js/app.js`, `android/app/src/main/java/ru/dorokhin/seyf/RuStoreReviewPlugin.java`, строки 52-87, `android/app/build.gradle`, строки 80-82.
4. **Запрет сети для веб-части в сборке для RuStore.** Сборка заменяет в `index.html` правило Content-Security-Policy на `connect-src 'none'`: даже случайный запрос из JavaScript наружу WebView не выпустит. Нативные SDK RuStore (пункты 1-3) этим правилом не ограничены. См. `build-lib.js`, строки 226-229, и `build-apk.js`, строка 137.
5. **Ссылки, которые открывает сам пользователь.** Нажатие на ссылку в карточке контакта или в окне «О приложении» (политика конфиденциальности, соглашение, сайт автора) открывает её в системном браузере или другом приложении. Само приложение при этом ничего не загружает. С версии 1.3.3 в «О приложении» есть «Частые вопросы», в одном из них ссылка на этот репозиторий (`www/js/faq.js`), а кнопка «Открыть RuStore» в окне покупки открывает страницу приложения в RuStore (`www/js/app.js`).

Встроенные модули чтения и показа кодов дисконтных карт работают с локальными библиотеками ZXing и JsBarcode. Их версии, лицензии и источники перечислены в [www/js/vendor/loyalty/README.md](www/js/vendor/loyalty/README.md).

## Разрешения Android

Разрешения приложения перечислены в [AndroidManifest.xml](android/app/src/main/AndroidManifest.xml).

- `INTERNET` - нужен SDK RuStore (покупка и проверка покупки, с 1.3.2 ещё проверка обновления и окно оценки), а также WebView для работы с локальными файлами приложения по адресу `https://localhost`.
- `USE_BIOMETRIC` - вход по биометрии, которую Android предоставляет приложению на этом устройстве.
- `CAMERA` - сканирование QR-кода при добавлении кода 2FA (`www/js/qr-scan.js`, строки 59-98), распознавание штрихкодов и QR-кодов дисконтных карт, съёмка документов (`www/js/doc-viewer.js`) и дисконтных карт (`www/js/loyalty-ui.js`). Камера не обязательна: `android.hardware.camera` с `required="false"`, секрет 2FA можно ввести вручную. Временные JPEG, которые камера оставляет в папке приложения, удаляются после съёмки и при запуске (`www/js/camtemp.js`); в сейф попадает только зашифрованная копия.

- `POST_NOTIFICATIONS` - с Android 13 требуется для уведомлений о сроках документов. Пользователь включает их сам.
- `RECEIVE_BOOT_COMPLETED` - для восстановления расписания уведомлений после перезапуска телефона.

Блок `<queries>` позволяет приложению на Android 11 и новее увидеть установленный RuStore, чтобы проверить обновление и показать окно оценки.

Новые в 1.3.3 нативные плагины печати и размера шрифта (`PrintPlugin.java`, `FontScalePlugin.java`) разрешений не требуют.

Подключённые библиотеки добавляют свои разрешения при сборке APK. В сборке 1.3.4 для RuStore также объявлены `VIBRATE`, `USE_FINGERPRINT`, `ACCESS_NETWORK_STATE` и служебное `ru.dorokhin.seyf.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. Список можно проверить командой `aapt2 dump permissions`. `VIBRATE` добавляет плагин `@capacitor/haptics` (вибро-отклик на ключевых действиях, `www/js/app.js`).

## Другие меры защиты

- Запрет скриншотов и записи экрана (`FLAG_SECURE`) и выключенная отладка WebView в релизной сборке. См. `android/app/src/main/java/ru/dorokhin/seyf/MainActivity.java`.
- Поля сейфа исключены из системного автозаполнения Android. См. там же.
- Лицензионный ключ полной версии проверяется офлайн по подписи ECDSA P-256; в приложение вшит только публичный ключ. См. `www/js/license.js`, строки 1-14.

## Чем исходник отличается от сборки в RuStore

Скрипт `build-apk.js --store` берёт папку `www/` и меняет в копии три вещи: в `buildflags.js` ставит `SEYF_STORE = true` и `SEYF_DEMO = false`, в `js/demo.js` выключает демо-режим, в `index.html` ставит `connect-src 'none'`. Ещё при сборке создаются служебные файлы: опись файлов `files.json` (`build-lib.js`, строки 243-262) и заглушки `cordova.js` и `cordova_plugins.js`, которые добавляет `npx cap sync` (`build-apk.js`, строка 154). Остальные файлы попадают в APK без изменений. См. `build-lib.js`, строки 181-233.

## Как проверить самому

1. **Режим полёта.** Включите режим полёта и пользуйтесь сейфом: создание, разблокировка, запись, резервная копия работают без сети. Без сети не сработают только покупка, восстановление покупки и проверка обновления через RuStore. «Архив для близких» тоже работает без сети.
2. **Прочитать шифрование.** Весь криптографический код сейфа - 115 строк в `www/js/crypto.js`. Как он вызывается - `www/js/app.js` и `www/js/storage.js`. Шифрование файла «Архива для близких» - `www/js/archive.js`.
3. **Найти сетевые вызовы.** В разделе «Сетевые обращения» перечислены файлы веб-кода и нативных мостов RuStore.
4. **Запустить тесты.** Для тестов нужен Node.js 22.12 или новее.

   ```
   npm ci
   npm test
   ```

   Проверки, которым нужны внутренние скрипты, материалы витрины или ключи подписи, пропускаются с указанием причины. Для браузерных тестов установите Chrome или Edge. Путь к браузеру можно задать переменными `LOYALTY_BROWSER`, `EDGE_PATH` и `SEYF_BROWSER` в зависимости от теста. Тесты шифрования находятся в `tests/crypto.test.mjs` и `tests/auth-crypto.test.mjs`.

## Сборка APK

`node build-apk.js` собирает тестовый APK (нужны JDK и Android SDK). Релизная сборка подписывается ключом автора, которого здесь нет, поэтому подпись вашего APK не совпадёт с приложением из RuStore.

## Лицензия

Код открыт только для просмотра и проверки. Распространять копии, собирать и публиковать свои версии, использовать код в других продуктах нельзя. Подробно - в файле `LICENSE`.

Сторонние библиотеки в `www/vendor/` (jsQR, pdf.js, fflate, шрифты) распространяются по своим лицензиям.
